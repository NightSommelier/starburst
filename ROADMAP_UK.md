## Архітектурні конвенції

- **Універсальний клієнт — ніколи не змінюйте офіційний сервер, лише вдосконалюйте клієнт.**
- **Постійний PTY**: при під'єднанні до сервера встановлюється одна довготривала термінальна
  сесія, яку Git, редагування файлів, інформація про залізо, перезапуск та інші операції
  **спільно використовують**, уникаючи повторних накладних витрат на запуск shell.
- Надавайте перевагу наявним REST API (`/config`, `/session/status`, `/global/health` тощо);
  все, чого REST не може, йде через постійний PTY із запуском shell-команд.
