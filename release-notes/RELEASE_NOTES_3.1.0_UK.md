# StarBurst v3.1.0 - Примітки до релізу

> Чернетка — 3.1.0 у розробці. Наведений нижче функціональний обсяг реалізовано та перевірено
> (компіляція + 272 JVM-юніт-тести); контрольні суми APK та release-тег заповнюються під час
> випуску.

Test Intelligence з'являється в застосунку разом зі сповіщеннями моніторингу серверів та
каналом синхронізації starburst-backend.

## Основне

- **Test Intelligence (клієнт)** — новий пункт у верхній панелі списку сесій (показується, коли
  під'єднано сумісний бекенд). Переглядайте intel-проєкти та модулі, інспектуйте функціональні
  точки із залученими endpoint'ами, запускайте одиночний тестовий прогін і читайте результати по
  кейсах, замикайте цикл по проблемах (позначити вирішеною, прив'язати до функціональної точки),
  переглядайте та застосовуйте пропозиції виправлень (попередній перегляд diff, режими запису
  file/patch/branch, відкат), і питайте AI в межах функціональної точки про відповідь із
  підв'язаним контекстом. Застосунок — легкий клієнт: важлива конфігурація (створення проєктів,
  списки дозволених команд, редагування правил) залишається у Web UI.
- **Сповіщення моніторингу серверів** — картка в керуванні сервером показує живі показники
  CPU / пам'яті / диска, пороги та перемикач увімкнення (`GET/POST /api/alerts`). Коли показник
  перетинає поріг, бекенд надсилає `alert.hardware`, і застосунок показує сповіщення (та ще одне
  при відновленні).
- **Синхронізація між пристроями через starburst-backend** — четвертий варіант сховища
  синхронізації віддзеркалює корисне навантаження у KV-таблицю `sync_bundle` бекенду
  (`GET/PUT /api/sync`) — для тих, хто вже має бекенд і надає йому перевагу перед Gist / WebDAV /
  файловим провайдером.
- **Push Test Intelligence** — застосунок підписується на події `intel.*` через `/api/ws` та
  сповіщає про завершені прогони та знахідки аудиту безпеки/відповідності.
- **База знань** — пункт у керуванні сервером відкриває KB: список/створення/видалення колекцій,
  список документів, приймання тексту/файлів та семантичний пошук зі сніпетами результатів
  (`/api/kb/collections`, `/api/kb/ingest`, `/api/kb/search`).

## Додано

- Test Intelligence: список проєктів, розділи feature/test/issue/fix по кожному проєкту,
  AI-чат функціональної точки, підсвітка SECURITY_WARNING.
- `BackendApi`: 23 методи, що покривають `/api/intel/*`, `/api/alerts` та `/api/sync`; DTO
  `IntelModels`, `BackendAlerts`, `BackendSync`.
- Друга підписка `/api/ws` (`intelEventFlow`) з типізованим парсером подій та трьома будівниками
  сповіщень (прогін завершено, апаратна тривога/відновлення, знахідка аудиту).
- Картка сповіщень моніторингу в керуванні сервером (показники + пороги + увімкнення).
- Варіант сховища синхронізації через бекенд (`BackendSyncTransport`, ключ `global`).

## Змінено

- `BackendGate.REQUIRED_BACKEND_VERSION` розділено на `MIN_BACKEND_VERSION` (шлюз оновлення) та
  `INSTALL_BACKEND_VERSION` (закріплення встановлювача); у цьому релізі обидва — **2.1.0**.
- Токен синхронізації starburst-backend тепер зберігається в `LocalSyncSecretStore` (Android
  Keystore AES-GCM) замість відкритого тексту в DataStore.

## Виправлено

- `update.json` рекламував v2.0.0; тепер вказує на випущений реліз v3.0.0 (коректне виявлення
  оновлень у застосунку).
- Чекбокси ROADMAP для Material You dynamic color та повнотекстового пошуку (уже реалізовано).
- **Виправлення за аудитом** — збій входу до бази знань (незареєстрований маршрут), виживання
  Intel push після перебудови SSH-тунелю, сповіщення про знахідки аудиту з рівнем `high`,
  збереження неспоріднених облікових даних при від'єднанні синхронізації, захист від OOM при
  прийманні KB + потокова обробка, дедуплікація історії тривог, перевірка того самого походження
  для попереднього перегляду/завантаження документів, сповіщення, що враховують налаштування
  користувача enable/silent, з локалізованими ID на сервер, одноразова міграція каналів.

## Безпека

- Токен синхронізації бекенду шифрується в стані спокою (Android Keystore AES-GCM), як і токен
  GitHub та пароль WebDAV.
- Синхронізація з бекендом приймає лише URL `https://` (або loopback), як і політика WebDAV —
  бекенд із звичайним HTTP відхиляється, бо токен Bearer був би викритий.

## Парність із бекендом

Ця версія вимагає starburst-backend **>= 2.1.0** (`BackendGate.MIN_BACKEND_VERSION`).

- Клієнт Test Intelligence, картка сповіщень моніторингу та канал синхронізації націлені на
  endpoint'и `/api/intel/*`, `/api/alerts` та `/api/sync`, які постачає лінійка бекенду 2.x.
- Встановлювач одним дотиком закріплює тег `v2.1.0` (`BackendGate.INSTALL_BACKEND_VERSION`).

```bash
curl -fsSL https://raw.githubusercontent.com/hiylo/starburst-backend/v2.1.0/scripts/install.sh \
  | sudo env STARBURST_DEFAULT_TOKEN=<your-token> bash -- --port 18880 --version 2.1.0
```

## Встановлення та перевірка

```bash
# Заповнити під час випуску:
sha256sum app-release-v3.1.0.apk
adb install -r app-release-v3.1.0.apk
```
