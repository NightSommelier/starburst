# Базова лінія продуктивності StarBurst

> Фіксує виміряні базові показники часу старту та пам'яті як орієнтири для подальшої оптимізації
> та порівняння регресій.
> Команди повторного вимірювання та методологія: `scripts/measure-startup.sh`. **Дані залежать
> від середовища; спершу зареєструйте свіжий запис у цьому документі.**

## Примітки щодо методології та застереження

- Наведені вище цифри — дані **debug + емулятор з програмним рендерингом**, лише для відносної
  регресії; дані release / справжніх пристроїв будуть помітно нижчими та потребують окремого
  вимірювання.
- Час старту включає холодний старт `MainActivity` (ініціалізація Compose, Hilt, запуск
  фонового `StarBurstConnectionService`); вимкнений debug додає ще більше накладних витрат.
- Базова лінія пам'яті не включає сценарій завантаження локальних моделей MNN (після завантаження
  моделей ASR/автодоповнення на вимогу RSS суттєво зростає — це очікувано).

## Повторне вимірювання

```bash
# Після під'єднання пристрою/емулятора:
APK=app/build/outputs/apk/debug/app-debug.apk bash scripts/measure-startup.sh 5
```

## Baseline Profile (введено 2026-09-22)

- Залежність `androidx.profileinstaller:profileinstaller:1.3.1` (застосовує AOT-профіль під час
  встановлення).
- Новий модуль `:baselineprofile` (`com.android.test` + `androidx.baselineprofile` 1.3.1 +
  керований пристрій `pixel2Api34`).
- Артефакт `app/src/main/baseline-prof.txt` (12 423 рядки; гарячий шлях холодного старту до
  головного екрана); об'єднаний ART-профіль release-збірки підтверджено підключеним:
  10 596 → 17 908 рядків.
- Генерація: `./gradlew :baselineprofile:connectedNonMinifiedReleaseAndroidTest`, потім
  `./gradlew :baselineprofile:collectNonMinifiedReleaseBaselineProfile`; артефакт потрапляє до
  `baselineprofile/build/outputs/connected_android_test_additional_output/.../BaselineProfileGenerator_generate-baseline-prof.txt`;
  скопіюйте його до `app/src/main/baseline-prof.txt`.

## Базова лінія на справжньому пристрої (2026-09-27, release-збірка)

> Додає раніше відсутній зріз «release + справжній пристрій». Цифри AVD вище — це debug +
> swiftshader програмний рендеринг, лише для відносної регресії — не порівнюйте їх напроліт
> з цим розділом.

### Середовище вимірювання

| Пункт | Значення |
|---|---|
| Збірка | `starburst-release-3.0.0-v2fix75.apk` (28 165 139 Б), підписаний release |
| Пристрій | Xiaomi 2308CPXD0C (Android 16 / MIUI, USB-налагодження) |
| Збір даних | `scripts/measure-startup.sh 5` (кожен запуск: `force-stop`, потім `am start -W` → `TotalTime`); пам'ять через `dumpsys meminfo` після 4с стабільного переднього плану |

### Холодний старт (TotalTime)

| Статистика | Значення |
|---|---|
| медіана | **272 мс** |
| середнє | 297 мс |
| сирі дані | 405 / 250 / 268 / 272 / 288 мс |

Порівняно з 1054 мс на AVD debug це приблизно у 3.9 раза швидше — розрив походить головно від
справжнього заліза та GPU-прискорення; **не робіть з цього висновків про виграш release проти
debug** (типи збірок та шляхи рендерингу різняться).

### Пам'ять (стабільний передній план)

| Показник | Значення |
|---|---|
| TOTAL PSS | **52 323 КБ** (~51.1 МіБ) |
| TOTAL RSS | 172 824 КБ (~168.8 МіБ) |
| TOTAL SWAP PSS | 240 КБ |

PSS практично на рівні з AVD (50 662 КБ, +1.6 МіБ), що відповідає очікуванню більшої кількості
фонових сервісів на справжньому пристрої.

### Частота кадрів / лаги: цього разу дійсних зразків немає

`dumpsys gfxinfo` під програмним прокручуванням відрендерив лише 3 кадри
(`Janky frames: 1 (33.33%)`); розмір вибірки недостатній, а перцентилі мають єдине значення
(36мс / 4950мс) — **статистично беззмістовно, тому не реєструємо**. Дійсна базова лінія лагів
потребує реальної взаємодії на справжньому пристрої (прокручування списку сесій + прокручування
довгої сесії + розгортання карток інструментів); це пункт вимірювання взаємодії на справжньому
пристрої.
